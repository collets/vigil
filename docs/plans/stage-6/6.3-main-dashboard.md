## Outcome and dependencies

Make the main screen the screen R45 says it must be: one view that, from a cold
start with no navigation, shows the active plan, the current task and its
blocker, the queue position, the live run and session state, the compact
per-task quality status and the actionable request list. Then turn History from
a wall of event labels into a navigable, filterable record.

This is the sub-stage that carries P15. It completes four register rows —
`status`, `events`, `queue` and `queue-list` — and adds **no new product
capability**; everything it shows and does already exists in the CLI.

Depends on 6.2's screen stack, focus model, scoped keys and help. No dependency
on any live route.

## What the candidate review changed, and what it cost

The candidate-wide review of `f4196fb` **rejected** it: one P0 and three P1s.
All are remediated, and two of them are worth stating plainly because they were
failures of *kind*, not of care.

**The P0 was a paper fix.** Round 1 found that "wall budget consumed" could not
be rendered, and the remediation added the field — read from `time_segments`, a
table with **no production writer at all**. Both new run screens therefore
rendered a structural zero that read as a measurement: the one property this
stage existed to establish, violated by the very fix for the defect that
prompted it. The read now comes from `active_segments`, the table the supervisor
actually writes, and carries `BudgetObserved` so absence is distinguishable from
a measured zero. `TestBudgetUnobservedNeverReadsAsZero` asserts it, and also
asserts `time_segments` is empty, so this cannot silently return.

**A P1 paired two different questions.** The run screen showed an attempt-scoped
limit against a task-cumulative charge, which misreports what remains after any
retry. They are now separate fields with separate labels.

**A P1 let a key act on something the screen never showed.** The queue cursor was
bounded by the queue length while the queue list renders ten rows, so past row
ten `u` could queue a plan with no visible row and no focus marker. The cursor,
the request cursor and the action itself are now bounded to the rendered window,
and the overflow notice says the remainder is not selectable here.

**A P1 was a documentation finding, not a code finding** — and the most useful
one. The Overview had been built to satisfy the plan's checkpoint-C sentence
("the run state and a one-line activity summary") rather than P15's own words
("the live run **and session state**"), and the P15 test asserted the
*absence* of `Session:`. A gate test that certifies the negation of a clause of
the condition it certifies is worse than no gate, because 6.9 would re-run it as
the P15 evidence. The session line is back on the Overview — one compact line,
not the identity wall that round 6 accepted — and the detail beyond it stays one
keystroke away. **No requirement was weakened to achieve this.**

Feature row 2.12 was also corrected from `done` to `partial` with its gap named,
because 6.2's reviewer had accepted the same "graces shown, not editable"
distinction and I recorded it as done anyway.

The honest summary: eight checkpoint reviews were not a substitute for one
review of the assembled candidate. Every one of the four findings was invisible
from inside the checkpoint that contained it.
