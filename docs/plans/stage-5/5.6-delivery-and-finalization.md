## Work checkpoints

### A. Exact-tree local commits

- [x] Prepare a commit operation bound to enrolled repository, base/parent, branch/ref, approved index/tree digest and task/evidence revisions. Recheck current state/authority before effect. Never silently include unrelated user files.
- [x] Use app-controlled Git invocation with explicit environment/config and no uncontrolled hooks/helpers; preserve the user's index/worktree. Journal creation and compare-and-swap ref updates separately where needed, retaining object identity for reconciliation.
- [x] Reconcile crashes after object creation or ref movement before retry. Existing commit objects are observations, not task acceptance or push authority. Support multiple task commits with precise evidence correspondence.

### B. Exact ref push and draft hosting request

- [x] Resolve and bind the remote/hosting identity, exact plan ref/object, destination base and draft flag. Treat commit, push and request creation as separate scoped operations with revocation/expiry/once semantics.
- [x] Push only the approved object/ref; reject force/mirror/wildcard, checkpoint refs, unexpected branch/ref changes and rewritten destinations. Protect against remote configuration changes between approval and start.
- [x] Add GitHub and GitLab draft-request adapters behind a common bounded interface. No merge endpoint/tool. Keep provider credentials in the trusted application, referenced by name and excluded from logs/artifacts.
- [x] On timeout/connection loss after possible success, persist uncertainty; inspect the exact remote ref or search by repository/head/base/operation identity before retry. Conflicting or ambiguous observations remain blocked, not duplicate requests.
- [x] Test each supported hosting adapter with fake API responses, pagination/rate/error bounds, duplicate candidates and draft-state verification. Self-hosted hosting remains deferred.

### C. Factual archive and independent narrative

- [x] Build an immutable manifest from persisted spec/plan/task/config revisions, criteria, check/review/manual evidence, usage provenance, commits, delivery observations and recovery status. Validate owned artifact digests and typed references before publication.
- [x] Persist the factual archive before optional model-written narrative. Make finalization a visible system task with its own plan-services allowance, selected profile, bounded result and reference/completeness validation. The bounded local Hermes route remains explicitly gated and still needs native qualification evidence.
- [x] Narrative failure becomes `finalization_pending`; accepted work remains accepted. Retry only finalization. Do not recursively generate finalization tasks or rerun development/checks without a relevant change.
- [x] Permit explicitly authorized draft delivery while narrative is pending. Append its URL/observations in a new manifest revision. An exported archive commit must not try to contain its own future commit ID.

### D. Export and retention

- [x] Export verified records with portable relative references and explicit external URLs. Refuse symlink/path escape and missing/corrupt required evidence; redact credentials rather than exporting ambient state.
- [x] Implement configurable completed-plan raw-transcript expiry with the 30-day default. Mark references expired before deleting eligible bytes and preserve extracted durable evidence/decisions indefinitely by default.
- [x] Exclude unfinished plans/checkpoints, unresolved operations and recovery dependencies from completion TTL. Native histories remain untouched; never purge global harness history or unowned files.
- [x] Add dry inspection of retention candidates and deterministic fake-clock tests before any real cleanup. Shared artifact references must prevent deleting bytes still needed elsewhere.

## Validation and completion

Use disposable repositories, local bare remotes and fake hosting servers for all routine delivery tests. Inject failures before/after commit/ref update, push response, request creation and observation commit. Assert exact refs/objects and at most one reconciled draft request. Test policy revocation, wrong remote/base, changed tree, stale approval and fake-server ambiguous results.

Test archive corruption, missing/expired references, narrative failure followed by finalization-only retry, delivery from pending finalization, portable export and retention with shared/unfinished dependencies. No test may mutate the user's actual Git remote or hosted repository by default. Run shared checks and platform-specific Git/filesystem tests.

do not read this slice's acceptance as evidence that any of those operations
works on a real remote — that evidence does not exist yet.

## Autonomy and user gates

All implementation and disposable commit/push/fake-hosting tests are autonomous
and are the complete required scope for accepting this slice. No human-gated
operation is required for acceptance; they are deferred to Stage 8 by the
decision recorded above.

A real push or draft request, when Stage 8 reaches it, needs a concrete
destination, head/base/object scope and applicable authorization; credentials may
also be needed. The existing repository URL does not supply that authority. No
purchases, paid hosting setup or paid narrative calls are authorized. The Stage
8 plan is where that authorization is requested, per operation.
