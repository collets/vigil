The first independent review confirmed the walkthrough's central result — finding
5.7-F1 is a real product defect, correctly diagnosed and fairly attributed to the
Stage 5.2/5.6 delivery path — and confirmed the matrix discipline, the
non-fabricable reviewer fixture, the genuine capability refusals and the fixture
baseline. It rejected the candidate on one evidence-integrity hole and several
overstated classifications.

Remediated:

- **P1 — vacuous safety assertions.** `ExecutionView` decoded `json:"state"` and
  `json:"allowed_next"`, but production sends `run_state` and
  `allowed_next_commands`. Two "no replay is offered" assertions therefore looped
  over an **always-empty slice** and could never fire, while the case details
  printed the decode artifact `[]` as an observation. The tags now match the
  production `RunView` exactly, and `decodeIsReadable` treats an empty or
  identity-less inspection as a *failure* rather than as safety. This is the
  precise failure the plan forbids: a case reported as passed when it did not
  happen. The controller-kill case had in fact been observing a completed run
  with a delivered submission, so `forbidsUncertainReplay` now distinguishes it: a
  `start` after a lost *pre-submission* controller is the documented safe path,
  not a replay, and only an `uncertain` submission must refuse it.
- **P2 — overstated evidence classes.** Milestone step 4 was `automated` although
  the plan requires an unavailable live route to be recorded as pending and
  **never** as passing; it is now `pending_stage_8` with the blocker named. R08
  and R20 claimed `automated` while their own details said pending/reused; R41,
  R42 and R69 described push, ref-set and reconcile events that did not occur. All
  are corrected. R09's reused citation named a record that never mentions it, so
  every carried citation is now **checked** — `sourceMentionsRequirement` demotes
  an unsupported citation to a gate with the reason recorded.
- **P2 — a product defect filed as a human gate.** 5.7-F1 was recorded
  `pending_stage_8`. `EvidenceUnmet` exists for exactly this, and the affected
  rows plus the draft milestone are now `unmet`, so the work is not filed as
  somebody else's to-do.
- **P3 — honest details under overstated names.** Four cases are now marked
  **partial**, and each names in its detail exactly what was and was not observed:
  the endpoint alias case did not queue a second waiter, `stale-owner-fenced` did
  not fence a real stale owner, `mixed-user-and-agent-work-preserved` did not clear
  and restore a mixed tree, and
  `partial-multi-repository-restore-is-visible` did not drive a genuinely partial
  restore.
- **P3 — an inert opt-in presented as a live turn.** The gate, probe and budget
  existed but no stage drove a turn. The report and the `scenario-live` comment
  now state plainly that a real bounded local Hermes turn is **not** yet driven

- **P4 — hygiene.** Removed the leftover `var _ = errors.New`. Separated the two
  gofmt-only changes to `internal/core/retention.go` and
  `internal/core/finalization_test.go` out of the feature commit. Guarded
