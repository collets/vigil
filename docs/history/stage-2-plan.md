## Work sequence and exit checks

1. **Baseline and profiles.** Run `make check`; verify installed versions and recorded Hermes source hashes. Prepare new private homes/fixtures. Recheck native settings and record config digests. Check llama health and authenticated model metadata without inference. Use existing Codex ChatGPT auth only, copied privately for the child and removed on normal exit. No model/provider substitution.
2. **Shared process transport (`internal/harness`).** Supervise argv/cwd/explicit environment with a dedicated process group, stdin writer, continuously drained stdout/stderr, bounded JSONL frames and queues, typed directional request IDs and RPC deadlines. Keep human response work off the reader. Unexpected EOF, malformed messages, oversize frames, capacity/evidence overflow and process exit are failures. Never replay a request after uncertain delivery. Bounded close escalates EOF/TERM/KILL, reaps the process and retires requests; no claim about detached writers outside the owned process group.
3. **Session/event model.** Keep run, application turn, native runtime/durable session and native turn identities separate. Normalize output/tool/request/usage/outcome/failure events; outcome and task acceptance remain separate. Validate terminal status, handle duplicates deterministically, preserve missing usage values, reject conflicting terminal events and stale answers. Approval/input lifetime is bound to transport generation and active turn. Unsupported requests receive a protocol error and stop the attempt.
4. **Codex adapter.** Initialize/initialized, inspect account and available model, create thread with explicit profile/workspace/policy, submit once with an output schema, stream events and inspect terminal turn. Support native one-time approval/denial and user-input responses in the adapter. Do not enable broad grants or automatic approval reviewers. Implement native interruption plus transport shutdown; deeper lifecycle proof remains Stage 3.
5. **Hermes adapter.** Wait for gateway.ready, inspect gateway capabilities, register server requests, create session, verify effective info (which may arrive after lazy creation), then submit once. Treat streaming acknowledgement separately from message.complete. Normalize file/command progress, questions, approvals and nullable usage. Handle request.cancel; reject queue/redirect/steer acknowledgement for a fresh task. Observe session idle before closing, without claiming that idle proves all detached work stopped.
6. **Development runner (`vigil spike`).** Accept one prepared manifest and harness. Default to metadata-only preflight; require `--live` for inference. Support a private llama key file. Validate fixture ownership/baseline/config freshness, prevent reuse/concurrent dispatch, enforce startup/RPC/request/active/wall/output limits, and handle Ctrl+C. Default native requests to deny/cancel in this noninteractive fixture runner; the adapter answer API is tested separately. Stream bounded activity metadata and write private sanitized events and a final report even on failure. Never persist raw credentials, stderr or arbitrary wire payloads. Independently verify exact expected bytes, unchanged check/instructions, complete Git diff and strict final JSON. Report fixture verification, never product task acceptance.
7. **Synthetic verification.** Test out-of-order/concurrent responses, string/number and bidirectional ID collisions, server requests while another RPC is pending, cancellation/deadline/late answers, malformed/oversize messages, event overflow, stderr pressure, disconnect/early exit, blocked stdin, bounded shutdown, terminal duplicates/conflicts, native mappings and invalid result/fixture cases. No routine tests contact a provider. Run `make check`, race tests for new concurrency code, build and Linux/macOS cross-compilation.
8. **Live verification and handoff.** Run one fresh Codex fixture and one fresh Hermes fixture sequentially. Record workspace/profile/session/turn IDs, observed activity, native completion, independently checked result/diff, usage availability and cleanup status. Retain failed attempts; after an implementation fix use a new explicitly launched fixture rather than automatic replay. Save reviewed evidence in `docs/research`, update capability claims and next steps, and commit the complete increment. macOS runtime, stressed cancellation, recovery and hard policy enforcement remain Stage 3 gates.

## Decisions and limits

- Go standard library transport, no new protocol framework; Python stays a preparation/installed-Hermes inspection helper.
- Prepared manifests are trusted local experiment inputs, not general external job definitions. Reprepare after moving a checkout or changing profiles. Only the generated disposable fixture may be the live workspace.
- One session and one application turn per transport. No automatic retries or provider/model fallbacks. Native internal API retries can exist but the application enforces a wall cap.
- Keep receive order for normalized events; register requests before writing, allow events to arrive before the submit response, and never let a duplicate response authorize extra work.
- Stage 1 bounds: 30s startup, 15s RPC, 180s active execution, 60s request wait, 300s absolute wall, 5s interrupt and 5s termination grace; 1 MiB frames, 16 MiB evidence, 256 queued events, eight pending requests. The runner denies requests immediately by default, so no human wait is charged to active time. Cleanup has its own bounded grace after a cancelled attempt.
- Diagnostics retain wire structure/method/size and normalized safe metadata; arbitrary prompts, arguments, token values and stderr text are omitted. The fixture's final summary/files result is validated before recording. Private native histories are separate from application diagnostics.
- `completed` is a native execution outcome. Fixture verification also requires the expected file and strict result, no extra edits and no contradictory transport evidence. Full acceptance still needs the later review/human workflow.

## Initial environment evidence

Baseline `make check` passed. Codex 0.155.1 and Hermes 0.21.3 at the Stage 1 commit remain installed. llama initially returned 401 with the existing Hermes credential. The user's inherited `OPENAI_BASE_URL` and `OPENAI_API_KEY` resolved authentication without creating a credential file. Authenticated metadata advertised `qwen3.8-27b-local`, 131072 context tokens, one slot, and tool/template support. Both live fixture runs subsequently passed.

Protocol references: [official Codex app-server](https://learn.chatgpt.com/docs/app-server) and installed generated schemas; pinned Hermes `tui_gateway/contracts`, `server.py`, `prompt_turn.py`, and request handlers. Installed-version source/schema discrepancies must be tested and recorded, not papered over.
