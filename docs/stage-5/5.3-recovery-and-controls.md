# Stage 5.3 — Recovery, checkpoints and execution controls

Status: planned. Prepared 2026-09-20 from `930ed37`.

## Outcome and dependencies

An interrupted or stopped plan preserves all recoverable work, exposes uncertain state honestly and resumes only through an eligible explicit choice. Users can pause future dispatch, stop an active run and save/restore work without losing their own edits. Repair/restart never resets cumulative limits. Original scope: C/E/F.

[5.2](5.2-repositories-and-execution.md) supplies repository maps, fingerprints, run identities, journals and initial budgets; [5.1](5.1-execution-qualification.md) supplies containment and independent writer/inference observations. Checkpoint algorithms and fixture tests can start before live qualification. No clearing/restoring real work while writers or ownership are uncertain. [5.4](5.4-quality-and-acceptance.md) consumes safe repair/reset behavior; [5.5](5.5-workflow-and-planning.md) exposes these commands in the UI.

## Work checkpoints

### A. Pause, stop and foreground shutdown

- [ ] Make pause a durable dispatch prohibition: current attempt may reach its boundary, but no next implementation/check/review/supervisor run begins. Continue is explicit and rechecks eligibility.
- [ ] Stop disables dispatch first, retires outstanding requests, interrupts once, waits bounded grace, terminates the owned boundary and records outcome/writer/inference facts separately. Repeated commands return receipts; late answers cannot authorize a replacement run.
- [ ] Apply the same bounded sequence on foreground exit and persistence failure. Preserve resources in quarantine whenever safety is unknown; never release because a PID disappeared or the Docker container alone stopped.

### B. Verified multi-repository snapshots

- [ ] Define versioned checkpoint-set and repository manifests including HEAD/branch, original index bytes/entries, tracked bytes/deletions/modes/symlink targets, scoped untracked paths, exclusions and content digests. Keep private artifacts outside writable worker mounts.
- [ ] Stop/prove writers, capture every participating repository, fsync/publish bundles and verify recovery readability before marking the entire set verified. Failure in repository B must prevent clearing A. Incomplete snapshots remain inspectable.
- [ ] Preserve staged versus unstaged versus untracked distinctions and mixed user/agent work. Exclude ignored files/secrets unless an explicit preservation rule covers them; unsupported kinds block cleanup. If Git objects/refs are required, use temporary indexes and scoped compare-and-swap application refs.
- [ ] Test checkpoint codecs with symlinks and modes even when a current execution profile rejects such layouts. Preservation support does not imply boundary admission support.

### C. Scoped clear and approved restore

- [ ] Separate save from clear. Only clear provably agent-owned differences to the recorded pre-attempt baseline, using per-path compare-and-swap against the captured post-attempt state. Ambiguous mixed edits require reconciliation, never guessed ownership.
- [ ] Journal per-repository/path progress. On partial clear, preserve the verified set and block dispatch until reconciled; never replay a broad destructive command.
- [ ] Restore requires authority bound to checkpoint set and current destination fingerprint. First snapshot and verify the destination, preflight every repository and apply with progress records.
- [ ] Exact-baseline restore round-trips full index/worktree state. Changed destinations require a conflict-preserving three-way workflow; preserve both originals after partial failure. Stale authorization or intervening edits reject the effect.

### D. Resume and budget reconciliation

- [ ] Classify restart state using exact native home/session/profile/workspace/generation and qualification for that history class. Offer exact resume only when proven eligible; missing/corrupt/unsupported history requires explicit fresh-context reconstruction or continued blocking.
- [ ] Fresh context includes accepted criteria, current fingerprints, checks/findings, previous outcome/uncertainty and remaining allowance. It is a new recorded attempt, not a replay disguised as resume.
- [ ] Complete 5.2's cumulative ledger across implementation/check/review/supervisor runs and restart gaps. Charge repair attempts separately from infrastructure retries; allow infrastructure retry only with proof of no delivered prompt/tool effects.
- [ ] Persist bounded supervisor eligibility on exhaustion; the actual assessment flow belongs to 5.4. Exhaustion preserves partial work and never accepts it or changes spending authority.

## Validation and completion

Use disposable repositories containing staged and unstaged edits to one file, untracked files, binaries, deletions, executable modes, symlinks and nested participating repositories. Compare bytes, index entries and manifests after round-trip. Inject snapshot corruption, disk/write failure, path replacement, concurrent manual edits and interruption after each apply step. Assert a failed snapshot clears none and conflicts retain both recovery copies.

Run lifecycle tests for pause during active work, stop during native wait, repeated stop, late request answers, controller death, missing/corrupt history, and a writer that outlives native transport. Verify resource quarantine and deadlines. Budget tests use controlled clocks/reopen rather than long sleeps. Real resume is qualified by recovery class and platform; unsupported classes stay visibly disabled.

Run shared checks and native Mac filesystem/process tests. Completion requires actionable CLI recovery commands, verified multi-repository preservation, safe partial-failure recovery and evidence that no scenario loses user-owned changes. UI controls may remain for 5.5, but the core commands must be usable and documented.

## Autonomy and user gates

User decision confirmed: destructive failure tests, including crash, checkpoint, clear and restore scenarios, are authorized only inside agent-owned disposable fixtures. Preserve all real checkout changes; defer ambiguous real recovery and record it for the user while continuing independent work. Do not ask again for this fixture-test permission.

Implementation, disposable restore approvals and injected-failure testing can run autonomously. This does not authorize clearing/restoring the user's real checkout or resolving mixed ownership by assumption. Never use the user's working repository to demonstrate destructive failure cases. No paid inference or remote publishing is necessary.
