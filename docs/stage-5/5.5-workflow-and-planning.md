## Outcome and dependencies

A foreground user can load a local Markdown spec, approve a proposed plan, queue it, inspect progress and evidence, answer scoped decisions, pause/stop/recover and complete human review. Models get only bounded role/session-scoped application operations. Original scope: H/I.

This is the broadest slice, kept together because planning proposals, human approval and task progression share the same revisioned command path. Implement its four checkpoints separately. UI and tool validation can start with fixtures; live actions depend on [5.1–5.4](README.md). This plan owns task/plan selection and user interaction, not duplicate lifecycle or acceptance logic. It must call the commands from 5.2–5.4.
