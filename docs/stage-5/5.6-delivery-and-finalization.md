## Work checkpoints

### A. Exact-tree local commits

- [ ] Prepare a commit operation bound to enrolled repository, base/parent, branch/ref, approved index/tree digest and task/evidence revisions. Recheck current state/authority before effect. Never silently include unrelated user files.
- [ ] Use app-controlled Git invocation with explicit environment/config and no uncontrolled hooks/helpers; preserve the user's index/worktree. Journal creation and compare-and-swap ref updates separately where needed, retaining object identity for reconciliation.
- [ ] Reconcile crashes after object creation or ref movement before retry. Existing commit objects are observations, not task acceptance or push authority. Support multiple task commits with precise evidence correspondence.

### B. Exact ref push and draft hosting request

- [ ] Resolve and bind the remote/hosting identity, exact plan ref/object, destination base and draft flag. Treat commit, push and request creation as separate scoped operations with revocation/expiry/once semantics.
- [ ] Push only the approved object/ref; reject force/mirror/wildcard, checkpoint refs, unexpected branch/ref changes and rewritten destinations. Protect against remote configuration changes between approval and start.
- [ ] Add GitHub and GitLab draft-request adapters behind a common bounded interface. No merge endpoint/tool. Keep provider credentials in the trusted application, referenced by name and excluded from logs/artifacts.
- [ ] On timeout/connection loss after possible success, persist uncertainty; inspect the exact remote ref or search by repository/head/base/operation identity before retry. Conflicting or ambiguous observations remain blocked, not duplicate requests.
- [ ] Test each supported hosting adapter with fake API responses, pagination/rate/error bounds, duplicate candidates and draft-state verification. Self-hosted hosting remains deferred unless explicitly configured and validated.

### C. Factual archive and independent narrative

- [ ] Build an immutable manifest from persisted spec/plan/task/config revisions, criteria, check/review/manual evidence, usage provenance, commits, delivery observations and recovery status. Validate owned artifact digests and typed references before publication.
- [ ] Persist the factual archive before optional model-written narrative. Make finalization a visible system task with its own plan-services allowance, selected profile, bounded result and reference/completeness validation.
- [ ] Narrative failure becomes `finalization_pending`; accepted work remains accepted. Retry only finalization. Do not recursively generate finalization tasks or rerun development/checks without a relevant change.
- [ ] Permit explicitly authorized draft delivery while narrative is pending. Append its URL/observations in a new manifest revision. An exported archive commit must not try to contain its own future commit ID.

### D. Export and retention

- [ ] Export verified records with portable relative references and explicit external URLs. Refuse symlink/path escape and missing/corrupt required evidence; redact credentials rather than exporting ambient state.
- [ ] Implement configurable completed-plan raw-transcript expiry with the 30-day default. Mark references expired before deleting eligible bytes and preserve extracted durable evidence/decisions indefinitely by default.
- [ ] Exclude unfinished plans/checkpoints, unresolved operations and recovery dependencies from completion TTL. Native histories need ownership-aware rules; never purge global harness history or unowned files.
- [ ] Add dry inspection of retention candidates and deterministic fake-clock tests before any real cleanup. Shared artifact references must prevent deleting bytes still needed elsewhere.
